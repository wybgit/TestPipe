# 总体设计

## 1. 当前定位

TestPipe 当前是一个小而完整的测试编排框架，主链路是：

`Case YAML -> TestCaseLoader -> Pipeline -> PipelineCompiler -> PipelineSpec -> TestEngine -> runs/`

它的目标很直接：

- 把测试流程写成显式步骤
- 把测试数据放进 YAML
- 把执行结果落到独立 run 目录

## 2. 当前主线

当前仓库只保留一个稳定 pipeline：

- `OnnxGitAtcPipeline`

主线步骤：

1. `fetchModelNode` 获取模型资源
2. `compileModelNode` 执行 ATC
3. `expected.om_path.exists` 检查输出

## 3. 分层

当前实现只需要理解 4 层：

- 用例层：YAML、Case 校验、Case 归一化
- 编排层：`Pipeline` DSL
- 执行层：`PipelineSpec`、`TestEngine`
- 基础设施层：Host/Device/Transfer/Trace

## 4. 核心原则

- `PipelineSpec` 是执行真相源
- `Pipeline` 只是构图 DSL
- `TestEngine` 是唯一执行入口
- 副作用统一经过 `ActionRunner`
- 简单断言优先写在 `expected`

## 5. 当前取舍

刻意保留的复杂度：

- 输入和属性分离
- 静态图编译
- 统一 trace 和工件目录

刻意删除的复杂度：

- 演示型断言节点
- 重复 authoring 边状态
- 多种等价 testcase 主格式

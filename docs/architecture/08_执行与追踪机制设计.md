# 执行与追踪机制

## 1. 执行入口

当前入口是 CLI：

```bash
testpipe run examples/testcases/onnx_git_atc.yaml
```

主链路：

1. 解析 YAML
2. 创建 Pipeline
3. 编译为 `PipelineSpec`
4. 执行节点
5. 写出 run 目录

## 2. TestEngine 负责什么

- 创建 `run_dir`
- 构造 `StepContext`
- 逐节点执行
- 汇总输出和 `expected`
- 写日志、工件、导图

## 3. StepContext

节点执行时可见：

- `inputs`
- `attrs`
- `host`
- `device`
- `transfer`
- `artifacts`

## 4. trace

当前 trace 由 `TraceRecorder + ActionRunner` 负责，记录：

- 执行命令
- 传输动作
- stdout/stderr

开启 `--debug` 时额外落盘：

- `trace.json`
- `reproduce.sh`
- `step.json`

## 5. run 目录

```text
runs/
  case_id_YYYYMMDD_HHMMSS/
    summary.json
    execution.log
    pipeline_graph.dot
    pipeline_graph.pdf
    resources/
    steps/
```

## 6. 当前原则

- 日志和追踪不是附加能力，而是执行模型的一部分
- 所有副作用必须可追踪
- 每个 case 必须有独立目录

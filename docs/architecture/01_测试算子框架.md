# 测试算子框架

## 1. 定位

`TestOp` 是 TestPipe 的最小执行单元。一个节点只做一步事。

当前推荐理解：

- `Pipeline` 决定顺序和依赖
- `TestOp` 决定这一步做什么

## 2. 最小接口

```python
class TestOp(ABC):
    spec: OpSpec

    def __init__(self, **attrs):
        ...

    def execute(self, step_context) -> dict[str, Any]:
        ...
```

`spec` 必须声明：

- `inputs`
- `outputs`
- `attrs`

## 3. 上下文

`execute(step_context)` 可使用：

- `step_context.inputs`
- `step_context.attrs`
- `step_context.host`
- `step_context.device`
- `step_context.transfer`
- `step_context.artifacts`

## 4. 当前规则

- 一个算子只做一步
- 输入输出先于实现
- 外部副作用统一经过 runtime，不直接裸调底层接口
- 节点属性用于默认值和在线覆盖，不参与图绑定

## 5. 当前内置算子

- `ResourceFetch`
- `ATCCompile`
- `PathExists`

其中主线默认只用前两个；`PathExists` 保留给需要显式断言节点的场景。

# 测试算子框架

本文档描述当前 TestPipe 中 `TestOp` 的真实实现方式。

## 1. 核心定位

`TestOp` 是 Pipeline 中的最小执行单元。

它负责：

- 声明自己的输入、输出和属性契约
- 在 `TestEngine` 调度下执行一步业务逻辑
- 通过统一上下文访问主机、设备、传输和 artifact 能力

源码位置：

- [test_op.py](/home/wyb/AscendCode/TestPipe/testpipe/core/test_op.py)
- [registry.py](/home/wyb/AscendCode/TestPipe/testpipe/core/registry.py)

## 2. 当前基类

```python
class TestOp(ABC):
    spec: OpSpec

    def __init__(self, **attrs: Any):
        self.attrs = attrs
        self.validate_attrs()

    @abstractmethod
    def execute(self, step_context) -> dict[str, Any]:
        ...
```

当前框架不再维护旧式的：

- `op_type`
- `category`
- `inputs: list[str]`
- `outputs: list[str]`

这些信息都统一收敛到 `OpSpec`。

## 3. OpSpec 契约

一个算子必须定义 `spec`：

```python
OpSpec(
    version="1.0",
    description="...",
    inputs=[PortSpec(...)],
    outputs=[PortSpec(...)],
    attrs=[AttrSpec(...)],
)
```

其中：

- `PortSpec` 描述输入输出端口
- `AttrSpec` 描述构造时的静态属性

## 4. 注册方式

当前通过 `@register_op` 注册。

注册名默认由类名推断：

- `EnvCheckOp -> EnvCheck`
- `ResourceFetchOp -> ResourceFetch`
- `ATCCompileOp -> ATCCompile`

注册表实现位于 [registry.py](/home/wyb/AscendCode/TestPipe/testpipe/core/registry.py)。

## 5. 执行上下文

`execute(step_context)` 内可使用的主要能力：

- `step_context.inputs`
- `step_context.attrs`
- `step_context.host`
- `step_context.device`
- `step_context.transfer`
- `step_context.artifacts`

这意味着算子既能读输入，也能统一记录命令、日志和产物。

## 7. 设计约束

### 7.1 单职责

每个算子只做一步。例如：

- `ResourceFetch` 只负责取资源
- `ATCCompile` 只负责编译
- `PathExists` 只负责判断结果文件是否存在

### 7.2 契约先于实现

新增算子时先把 `OpSpec` 定清楚，再写 `execute()`。

### 7.3 通过目录体现分类

当前按目录划分能力，不再在代码里重复维护业务分类字段。

例如：

- `testpipe/ops/builtin.py`
- `testpipe/ops/resource/`
- `testpipe/ops/atc/`

### NPU算子/模型测试框架 原始需求与设计目标汇总表

#### 一、 框架定位与基础能力诉求
1. **测试场景覆盖：** 主要用于端侧 NPU 的算子测试。需要同时支持单点功能测试（算子级）和端到端场景测试（Host侧模型转换 -> Device侧模型推理）。
2. **底层指令封装 (AW封装)：** 最底层需对基本指令进行 Action Word (AW) 封装，测试流程需通过调用这些指令来描述。
3. **分层解耦设计：** 具备明确的分层（底层指令 -> 测试流程/Pipeline -> 测试用例资源），实现“测试流程逻辑”与“测试用例资源（如模型文件、源码）”的彻底解耦，因为同一个模型可能用于不同的测试点。
4. **部署与分发：** 框架基于 Python 开发，需支持编译为 `.whl` 包进行部署安装。

#### 二、 架构模式与规范约束诉求
5. **AI编译器级架构映射：** 框架需借鉴 AI 编译器的概念。Node 等价于算子（测试节点的IR描述），Pipeline 等价于构图/模型（支持子结构Block），执行测试等价于不同输入数据的模型推理。
6. **节点 (Node) 分类与设计：** 测试 Node 需要像 AI 算子一样有明确的分类。写 Node 就是写算子的底层实现。
7. **统一规范与强约束：** Node 和 Pipeline 的构造必须遵循统一的规范，框架注册时需进行检查约束，防止开发者随意变形导致框架混乱。
8. **去 Pytest 化探索：** Pytest 不是必须的，要求探索并实现基于 Pipeline 串行图执行引擎的调度方式，拿掉 Pytest 以满足自定义测试引擎的灵活度。

#### 三、 流程编排与可视化诉求
9. **Pipeline流水线流转：** 测试流程像流水线一样。测试资源作为输入传递到每个 TestNode，每个节点处理后可进行结果断言，串联形成端到端的测试流程。
10. **可视化图显式输出：** 必须有功能显式地输出 Pipeline 的流程图（如 DOT 图或通过 Protobuf 导出 ONNX 格式图），供用户检查自己构造的 Pipeline 是否符合预期。
11. **图信息丰富度：** 图上不能只是简单的流程，必须包含并展示出具体的测试点、节点参数等关键信息（例如使用 Netron 工具打开查看）。

#### 四、 用例编写与海量数据驱动诉求
12. **极简“填空式”用例：** 用户写用例就像对着 Pipeline 的模板或图“填空”。用例文件只负责讲清楚三件事：输入参数、使用的过程（Pipeline）、输出校验规则。
13. **自定义构图：** 绝大部分用户指定框架内置的 Pipeline 即可完成测试，但也允许用户使用 Node 自由构图。
14. **海量算子测试适配 (数据驱动)：** 面临几百上千个算子的测试，框架需支持使用 CSV 或 Excel 表格来承载用例参数输入，并能批量执行。
15. **流程参数覆盖：** 配置文件或内置 Pipeline 中的默认参数，在具体的用例实现中必须支持值的灵活覆盖。

#### 五、 通信、环境与资源调度诉求
16. **统一 Host/Device 通信：** 框架需提供统一的通信能力。支持先在 Host 侧处理，再通过 SSH/Telnet 下发指令或回传结果。
17. **多维环境适配与配置：** 支持通过配置文件或环境变量指定执行机和单板环境。Host 侧默认使用本机，也需支持指定使用 Docker 容器环境进行转换或编译。
18. **智能资源传输机制：** 支持 SFTP 或 NFS。需考虑到模型文件可能过大，纯传输耗时过长或板端存储空间不足的情况，框架需有机制（如 NFS 挂载）来解决大文件在远端单板的使用问题。资源需支持通过内部指令自动从 Git 仓获取。

#### 六、 调试排障与日志复现诉求
19. **透明化降级复现 (TVM Lowering 理念)：** 抽象的高层测试图需能经过框架转换映射，解析为每一步的基本底层指令（Bash 或 Python 指令）。
20. **无感追踪机制：** 在写 Node 时尽量避免繁琐的显式降级逻辑，期望有更好的方式（如隐式记录调用）将底层指令导出为可直接供用户 debug 和本地复现使用的脚本。
21. **隔离的沙箱级日志：** 每个测试用例必须单独输出到一个隔离的文件夹中。测试每一步的输出日志必须清晰可见可查，方便排障。
22. **精细化 Log 控制：** 执行过程中支持动态调整 log 级别，能够输出非常详细的底层交互信息。

#### 七、 大模型 (LLM) 原生适配与生态诉求
23. **用例天然适配大模型生成：** 框架架构需为 AI 自动生成用例服务。期望用户只给出“测试特性和测试点”，大模型就能自动生成对应的结构化测试用例（填空数据）。
24. **Prompt / Schema 自动注册与导出：** 在注册 Node 和 Pipeline 时，需要能提供或自动提取对应的 Skills/Prompt/IR 参数信息，供第三方 AI 工具理解框架规范。
25. **API 网站导出功能：** 框架需要有办法读取编写好的 Node 和 Pipeline，离线导出这些 API 的参数规范和说明，自动建立一个 API 网站或文档库供用户查阅。

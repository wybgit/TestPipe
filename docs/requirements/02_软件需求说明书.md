# TestPipe 软件需求说明书

## 1. 目标

TestPipe 的目标不是做通用工作流平台，而是提供一个面向 NPU 测试场景的最小编排框架。

当前收敛目标：

- 用 `Pipeline` 描述测试流程
- 用 `TestOp` 描述单步能力
- 用 YAML 填测试数据
- 用统一引擎执行并沉淀结果

## 2. 当前范围

当前稳定支持：

- Python DSL 构图
- YAML 用例加载与校验
- 静态图编译为 `PipelineSpec`
- Host 本地执行
- SSH/SFTP 基础能力
- `runs/` 目录下的日志、工件、导图

当前稳定主线：

- `OnnxGitAtcPipeline`

流程：

1. 获取 Git 资源
2. 执行 ATC 转换
3. 使用 `expected` 检查输出

## 3. 核心约束

### 3.1 单一执行入口

- 执行统一通过 `TestEngine`
- 不允许维护第二套主 runtime

### 3.2 单一真相源

- `PipelineSpec` 是执行真相源
- 导图、校验、文档都基于同一份静态结构

### 3.3 副作用集中

- 外部命令、设备动作、文件传输统一经过 `ActionRunner`
- `TestOp` 不直接绕过运行时调用底层系统

### 3.4 参数语义固定

- `inputs`：图里流转的值
- `attrs`：节点行为参数

### 3.5 简单断言优先放到 `expected`

- 路径存在性这类简单检查不再默认建成节点
- 只有校验逻辑本身需要复用或参与图结构时，才单独建断言节点

## 4. 关键对象

- `Pipeline`：构图 DSL
- `TestOp`：单步能力
- `PipelineSpec`：编译后的静态图
- `CaseSpec`：归一化后的单 case
- `EnvProfile`：运行环境
- `TestEngine`：执行器

## 5. 推荐 testcase 格式

推荐主格式：

```yaml
pipeline:
  name: PipelineName
  nodes:
    someNode:
      key: value

cases:
  - case_id: case_001
    nodes:
      someNode:
        key: override
    expected:
      output_key:
        exists: true
```

说明：

- `pipeline.nodes` 放通用节点参数
- `cases[*].nodes` 放单 case 覆盖参数
- `expected` 放简单结果检查

## 6. 非目标

当前不追求：

- Web UI
- 分布式调度
- 条件/循环/Block 执行模型
- CSV/Excel 批量数据驱动的完整实现
- ONNX 作为执行格式
- 完整 AW/Provider 生态

## 7. 未来方向

如果后续继续扩展，优先级建议是：

1. 扩展更多真实测试 pipeline
2. 扩展更多 `TestOp`
3. 在不破坏当前简洁模型的前提下补充批量数据驱动

不建议在主线能力未成熟前继续增加抽象层。

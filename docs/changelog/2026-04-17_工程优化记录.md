# 2026-04-17 工程优化记录

## 背景

本轮优化目标是让当前实现更符合奥卡姆剃刀原则：

- 保留真正有价值的统一执行模型
- 去掉重复状态和演示型复杂度
- 提供更直接、更易懂的 testcase 主格式

## 本次改动

### 1. 精简 Pipeline authoring 层

- 删除了 `Pipeline` authoring 层内部的重复边状态，不再在内存中同时维护 `node.inputs` 和重复的 authoring 边列表
- `PipelineCompiler` 继续以节点输入绑定为唯一事实来源推导 `EdgeSpec`
- `connect()` 保留为兼容 API，但不再维护第二份 authoring 边数据

影响文件：

- `testpipe/core/pipeline.py`
- `testpipe/core/compiler.py`

### 2. 引入更清晰的 YAML 主格式

- 新增推荐主格式：`pipeline.nodes` 与 `cases[*].nodes`
- 保留旧的“直接在 `pipeline` / `cases[*]` 下写节点名”的兼容读取能力
- 当 `nodes` 容器和旧直写格式在同一层同时声明同名节点时，显式报错，避免隐式覆盖

影响文件：

- `testpipe/loaders/testcase_loader.py`
- `examples/testcases/onnx_git_atc.yaml`

### 3. 收缩主线 Pipeline

- 内置 `OnnxGitAtcPipeline` 从 3 节点收缩为 2 节点
- 删除主线中的 `checkOmExistsNode`
- 保留 `PathExistsOp` 作为通用算子，不再把它作为默认主线的一部分

当前主线：

1. `fetchModelNode`
2. `compileModelNode`

影响文件：

- `testpipe/pipelines/atc/compile.py`

### 4. 简单结果检查回归 `expected`

- `expected` 新增对路径存在性的原生支持
- 现在可直接写：

```yaml
expected:
  om_path:
    exists: true
```

这样可以避免只为“文件是否存在”额外增加一个断言节点。

影响文件：

- `testpipe/engine/result.py`

### 5. 文档同步

- 更新了 README
- 更新了核心架构说明
- 更新了 Pipeline / Node API 示例
- API catalog 重新基于当前注册表导出

## 设计取舍

### 保留的部分

- `PipelineSpec` 作为执行真相源
- `TestOp.spec` 的输入/输出/属性契约
- `TestEngine` 统一执行
- `ActionRunner` 统一记录副作用

### 刻意没有做的部分

- 没有移除 `connect()` / `add_step()` 等兼容 API，避免直接破坏已有写法
- 没有删除旧 testcase 格式，只是把它降级为兼容模式
- 没有修改 `PathExistsOp` 本身，保留给更复杂的 pipeline 使用

## 结果

本轮优化后，项目的默认心智模型更简单：

- Pipeline 只描述真正的业务步骤
- 简单结果判断放在 `expected`
- YAML 默认使用 `nodes` 容器，不再依赖顶层隐式节点解析
- 图结构只维护一份事实来源

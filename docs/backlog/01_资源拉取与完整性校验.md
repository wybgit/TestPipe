# 资源拉取与完整性校验

## 1. 背景

当前框架已经支持:

- 本地单文件资源输入
- 资源复制到运行目录后执行

当前尚未支持:

- 指定本地文件夹作为测试资源
- 指定 Git 仓库中的某个文件夹作为测试资源
- 资源拉取后的完整性校验
- 拉取结果的稳定复现与版本冻结

这会直接影响真实模型、数据集、配置目录的测试可用性。

## 2. 需求目标

需要支持两类输入资源:

1. 本地文件夹
   - 支持相对路径
   - 支持绝对路径

2. Git 仓库中的文件夹
   - 支持仓库 URL
   - 支持固定版本 `ref`
   - 支持仓库内 `subpath`

在执行前，需要先完成:

1. 拉取或复制资源
2. 校验资源完整性
3. 将资源物化到本次执行工作区
4. 再进入后续 Pipeline 执行

## 3. 推荐输入模型

建议新增统一输入结构 `resource_ref`，不要继续只依赖单一 `resource_path`。

### 3.1 本地目录

```yaml
inputs:
  resource_ref:
    kind: local_dir
    path: examples/models/resnet50
    integrity:
      mode: manifest_sha256
      value: "3b9f..."
```

### 3.2 Git 仓库目录

```yaml
inputs:
  resource_ref:
    kind: git_dir
    repo: https://github.com/your-org/model-zoo.git
    ref: 4f2d6b1b8f3f2f6b7c9d1e2a3b4c5d6e7f8a9b0c
    subpath: models/resnet50
    integrity:
      mode: manifest_sha256
      value: "8c21..."
    git:
      lfs: true
```

## 4. 推荐实现方案

建议新增一个独立算子:

- `ResourceMaterializeOp`

职责:

1. 解析资源来源
2. 拉取或复制资源
3. 生成目录清单 manifest
4. 计算 manifest 哈希
5. 校验完整性
6. 将资源物化到本次 run 的 `artifacts/resources/`

建议输出:

- `resource_root`
- `resource_manifest_sha256`
- `resolved_source`
- `integrity_ok`

## 5. 完整性校验建议

### 5.1 校验方式

对目录内文件按相对路径排序，记录:

- `path`
- `size`
- `sha256`

再对整个 manifest 计算一个总 `sha256`，作为目录级完整性签名。

### 5.2 推荐 manifest 结构

```json
{
  "type": "directory_manifest",
  "file_count": 12,
  "total_bytes": 7340032,
  "files": [
    {"path": "model.onnx", "size": 1234, "sha256": "..."},
    {"path": "config/config.json", "size": 456, "sha256": "..."}
  ]
}
```

### 5.3 校验规则

- 如果声明了 `integrity.value`，执行时必须匹配
- 不匹配直接 fail
- fail 时禁止进入编译、传输、设备执行阶段

## 6. Git 拉取建议

推荐优先使用 sparse checkout，而不是全量 clone。

建议流程:

```bash
git clone --filter=blob:none --no-checkout <repo> <cache_dir>
git -C <cache_dir> sparse-checkout init --cone
git -C <cache_dir> sparse-checkout set <subpath>
git -C <cache_dir> checkout <commit>
```

如仓库使用 Git LFS:

```bash
git -C <cache_dir> lfs pull --include "<subpath>"
```

要求:

- Git 场景必须最终解析成 commit SHA
- 不建议把 branch 当成最终可复现版本

## 7. 缓存建议

建议在宿主机增加资源缓存目录:

```text
.testpipe/cache/resources/
```

缓存 key 可由以下信息生成:

- 本地目录: `abs_path + manifest_sha`
- Git 目录: `repo + commit + subpath`

目标:

- 避免重复拉取
- 让资源准备阶段更稳定
- 提升真实案例执行效率

## 8. 日志与输出建议

普通模式建议只显示:

- 资源来源
- 解析后的 commit
- 文件数
- 总大小
- 完整性是否通过

Debug 模式再输出:

- `resource_manifest.json`
- `resource_lock.json`
- Git 拉取与校验细节

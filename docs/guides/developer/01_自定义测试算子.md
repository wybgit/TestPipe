# 开发指南 - 自定义测试算子

## 1. 目标

本文档说明如何按当前 TestPipe 的真实实现新增一个 `TestOp`。

当前框架下，一个算子需要满足三件事：

- 有稳定的 `OpSpec` 输入输出契约
- 能在 `TestEngine` 中被统一执行
- 能被日志、trace、artifact 和图导出系统感知

## 2. 当前契约模型

自定义算子时，不再定义旧式的 `op_type`、`category` 字段。

当前需要显式维护的是：

- `spec.version`
- `spec.description`
- `spec.inputs`
- `spec.outputs`
- `spec.attrs`

算子名由注册器根据类名推断：

- `ATCCompileOp -> ATCCompile`
- `ResourceFetchOp -> ResourceFetch`

## 3. 最小实现模板

```python
from pathlib import Path

from testpipe.core import TestOp, register_op
from testpipe.spec import AttrSpec, OpSpec, PortSpec


@register_op
class PathExistsOp(TestOp):
    spec = OpSpec(
        version="1.0",
        description="Check whether a path exists",
        inputs=[
            PortSpec(name="target_path", type="artifact:path", description="path to inspect"),
        ],
        outputs=[
            PortSpec(name="path_exists", type="bool", description="path existence result"),
        ],
        attrs=[
            AttrSpec(name="expand_user", type="bool", required=False, default=True, description="expand ~ before checking"),
        ],
    )

    def execute(self, step_context) -> dict[str, bool]:
        raw_path = str(step_context.inputs.require("target_path"))
        target = Path(raw_path).expanduser() if step_context.attrs.get("expand_user", True) else Path(raw_path)
        return {"path_exists": target.exists()}
```

## 4. 设计约束

### 4.1 一步只做一件事

推荐把流程拆成单职责算子，例如：

- `EnvCheck`
- `ResourceFetch`
- `ATCCompile`
- `PathExists`

不要把多阶段逻辑塞进一个巨型算子里。

### 4.2 通过 `step_context` 访问能力

当前建议使用：

- `step_context.inputs`
- `step_context.attrs`
- `step_context.host`
- `step_context.device`
- `step_context.transfer`
- `step_context.artifacts`

不要在算子里直接绕过框架去写裸 `subprocess.run` 或自建连接逻辑。

### 4.3 输入输出尽量稳定

如果某个值需要被下游节点消费，就应该放进 `outputs`。

如果某个值只是控制本节点行为，不需要传播给下游，则放进 `attrs` 或节点直输输入。

## 5. attrs 和 inputs 的区分

建议使用下面的判断规则：

- `inputs`：每次 case 可能变化、也可能来自上游节点的值
- `attrs`：算子作者设定的结构化默认行为

例如 `ATCCompileOp`：

- `model_path / soc_version / atc_options / env_script / output_name` 是输入
- `timeout / framework` 是 attrs

## 6. 注册与目录组织

当前算子通过 `@register_op` 注册。

推荐目录：

```text
testpipe/ops/
  builtin/
  resource/
  atc/
  assertions.py
```

按能力目录划分即可，分类通过文件夹体现，不需要额外在代码里重复写分类字段。

## 7. 测试建议

每个新算子至少补三类测试：

- 契约测试：`spec.inputs / outputs / attrs` 是否符合预期
- 成功路径测试：正常输入时能否产出预期输出
- 失败路径测试：缺文件、命令失败、参数非法时是否有明确报错

如果算子会触发外部命令，还应补：

- trace 记录测试
- artifact 落盘测试

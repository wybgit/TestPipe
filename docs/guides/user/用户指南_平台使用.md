# TestPipe 平台使用指南

## 1. 快速开始

### 1.1 安装

```bash
pip install -e .
```

### 1.2 运行主线示例

当前 `examples/testcases/` 目录只保留一个主线案例:

```bash
testpipe run examples/testcases/onnx_git_atc.yaml
```

该案例会执行:

1. 从 Git 仓拉取指定模型目录或文件
2. 提取匹配的 ONNX 模型
3. 调用 CANN `atc` 转换成 `om`
4. 校验产物是否存在

---

## 2. 当前用例文件格式

TestPipe 当前统一使用两段式结构:

```yaml
pipeline:
  name: OnnxGitAtcPipeline
  fetchModelNode:
    repo: https://github.com/wybgit/onnx-layer.git
    path: Abs_testcase_5a6b43
    model_pattern: "*.onnx"
  compileModelNode:
    soc_version: Ascend310P3
    env_script: /home/wyb/Ascend/cann-8.5.0/set_env.sh
  assertOmExistsNode:
    expected_value: true
cases:
  - case_id: onnx_git_atc_case
    description: 验证从 Git 仓获取 ONNX 并成功完成 ATC 转换
    level: P0
```

含义如下:

- `pipeline.name`: 指定目标 Pipeline
- `pipeline.<NodeName>`: 该节点的通用输入赋值
- `cases[*].case_id`: 用例唯一标识
- `cases[*].description`: 用例描述
- `cases[*].level`: 用例级别
- `cases[*].<NodeName>`: 该用例对节点输入的差异化覆盖

填写规则:

- 顶层只保留 `pipeline` 和 `cases`
- 节点参数直接按 `节点名 -> 输入k-v` 书写
- 通用值写到 `pipeline`
- 差异值写到具体 `case`
- 不要给被上游边驱动的端口手动赋值

## 3. 环境配置

环境配置不再写进用例文件，而是统一由框架配置文件管理。

默认行为:

- 默认使用当前宿主机本地环境
- 通过 `testpipe.config.yaml` 声明命名环境
- 当前配置只体现 `local`、`docker`、`ssh`

常用命令:

```bash
testpipe run examples/testcases/onnx_git_atc.yaml
testpipe run examples/testcases/onnx_git_atc.yaml --config testpipe.config.yaml --env-profile local
```

---

## 4. 日志与结果

控制台日志按节点显示，只保留关键内容:

- `INPUT`: 节点输入
- `EXEC`: `I / B / O`
- `OUTPUT`: 输出与校验结果

最后会输出单独的 `SUMMARY` 面板，包含:

- 用例信息
- 执行结果
- 总耗时
- 输出目录

运行目录下会保留:

- `summary.json`
- `execution.log`
- `resources/`
- `steps/<step>/command.sh`
- `steps/<step>/execution.log`
- `steps/<step>/stdout.log`
- `steps/<step>/stderr.log`
- `steps/<step>/result.json`

---

## 5. 常用命令

```bash
testpipe list-pipelines
testpipe list-templates
testpipe list-skills
testpipe check-case examples/testcases/onnx_git_atc.yaml
testpipe run examples/testcases/onnx_git_atc.yaml --debug
testpipe show-template case-template
testpipe run-skill case-checker /path/to/check_case.yaml --json
testpipe run-skill case-runner /path/to/run_case.yaml --json
```

---

## 6. 说明

- 旧格式 `test_case` / `test_suite` 仍兼容读取，但不推荐继续新增
- 当前文档和示例统一以 `pipeline + cases` 为准
- 外部 AI 代理推荐通过模板和 `run-skill --json` 间接调用框架

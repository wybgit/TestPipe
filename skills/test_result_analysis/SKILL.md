# Skill: Test Result Analysis

## 目标

根据一次 TestPipe 运行的结果目录、`summary.json`、日志和步骤产物，输出结构化问题分析。

## 适用场景

- 某个 testcase 失败，需要快速定位根因
- 对比两次运行结果，判断是否是环境波动
- 将执行日志整理成可读的问题报告

## 先读这些文件

- `docs/architecture/08_执行与追踪机制设计.md`
- `docs/architecture/09_软件时序调用图.md`
- 目标 run 目录下的 `summary.json`、`execution.log`、`steps/*`

## 工作流程

1. 复制 `templates/request.template.yaml`，填入本次 run 目录和关注点。
2. 按步骤梳理:
   - 哪个 step 失败
   - 输入、输出和命令是否异常
   - 是否存在环境、资源、权限、参数问题
3. 输出结构化报告:
   - 结论
   - 证据
   - 根因判断
   - 修复建议
   - 是否建议重试

## 产出要求

- 结论必须绑定具体 step、文件或命令
- 明确区分“确定证据”和“推断”
- 如果信息不足，直接指出缺少哪些日志或配置

## 验收检查

- 不只复述日志，要给出可执行的下一步建议
- 如果是环境问题，要说明影响范围
- 如果是 testcase 或代码问题，要指出最可能需要修改的文件
